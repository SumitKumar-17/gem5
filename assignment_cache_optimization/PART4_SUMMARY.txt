QUESTION A: PERFORMANCE BOTTLENECKS
-----------------------------------

Primary Bottleneck: L1D Cache Misses
  • 16kB L1D: 28,564 misses → 8.23B ticks (worst)
  • 64kB L1D: 1,639 misses → 7.15B ticks (best)
  • Impact: 13.1% performance variation

L2 Misses: NOT a bottleneck
  • Only ~2,000 L2 misses (compulsory/cold-start)
  • Constant across all configurations
  • L2 hit rate >90% for most configs

Memory Requests Reaching Main Memory:
  • Optimal config (64kB/128kB/4/4): 0.0029% of memory ops
  • Only 24 requests reach memory (compulsory misses)
  • Cache hierarchy filters 99.997% of memory traffic

Conclusion: L1D is THE performance-critical component

QUESTION B: CACHE EFFICIENCY
-----------------------------

Best Hit Rate: L1 Instruction Cache (L1I)
  • 99.98% hit rate (constant across all configs)
  • Reasons:
    - Tight loop structure (excellent temporal locality)
    - Small instruction footprint (<100 instructions)
    - Sequential execution (spatial locality)

Second Best: L1 Data Cache (L1D) with 64kB
  • 99.80% hit rate when properly sized
  • Entire 48KB working set fits
  • Capacity-driven excellence

L2 Size vs Associativity:
  • NEITHER is important for this workload
  • L2 size 128kB-1MB: <0.001% difference
  • L2 assoc 4-16 way: No measurable impact
  • Working set fits in smallest L2 tested

Conclusion: Win the battle at L1D, not L2

QUESTION C: COST-BENEFIT TRADE-OFFS
------------------------------------

Smallest Config @ 90% Peak Performance:

DESIGN INSIGHTS & LESSONS
================================================================================

1. L1D Dominance Principle
   "Cache hierarchy performance is dominated by L1D size"
   - 13.1% impact vs <3% for all others
   - Prioritize L1D in silicon budget allocation

2. Associativity Sweet Spot
   "4-way L1 associativity is optimal; more is counterproductive"
   - 2-way: conflict misses
   - 4-way: optimal balance
   - 8-way: access latency penalty

3. L2 Irrelevance for Small Working Sets
   "Don't waste silicon on oversized L2 when working set fits L1D"
   - 128kB L2 sufficient for 48KB working set
   - Larger L2 provides zero benefit

4. Hit Rate Paradox
   "High L2 hit rate indicates poor L1D, not good L2"
   - 95.7% L2 hit rate = WORST performance (8.23B ticks)
   - 1.5% L2 hit rate = BEST performance (7.15B ticks)
   - Optimize total time, not individual metrics

5. Pareto Frontier Guides Design Space
   "Only 3 of 108 configs are optimal; others are dominated"
   - Pareto frontier is designer's friend
   - Choose based on constraints (perf/power/cost)

6. Multi-Parameter Analysis Essential
   "Single-parameter sweeps miss dominant factors"
   - Part 2 focused on LEAST important parameter
   - Part 3 revealed TRUE performance driver
   - Always sweep suspected bottlenecks
