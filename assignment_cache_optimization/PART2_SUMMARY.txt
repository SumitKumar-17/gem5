================================================================================
KEY FINDINGS
================================================================================

1. PERFORMANCE SATURATION AT 256kB
   ✓ Performance saturates at 256kB L2 cache
   ✓ Larger caches (512kB, 1MB) provide zero additional benefit
   ✓ Working set (~48KB) fits comfortably in 256kB L2

2. MINIMAL PERFORMANCE IMPACT
   ✓ Only 0.0048% improvement from smallest to largest L2
   ✓ L2 size is NOT a bottleneck for this workload
   ✓ L1D cache effectiveness (96.56% hit rate) reduces L2 pressure

3. COMPULSORY MISSES DOMINATE
   ✓ ~2,000 L2 misses are cold-start misses
   ✓ Cannot be eliminated by increasing cache size
   ✓ Represent initial data loading before caching helps

4. WORKING SET MATTERS MORE THAN CACHE SIZE
   ✓ Cache must be >= working set size
   ✓ Beyond that threshold, size doesn't matter
   ✓ Cost-effective design: size cache to working set, not arbitrarily large

================================================================================
ANALYSIS HIGHLIGHTS
================================================================================

Trends Observed:
  - Execution time shows negligible variation across L2 sizes
  - L1 hit rates completely constant (unaffected by L2 size)
  - L2 hit rates nearly identical (92.99% - 93.00%)
  - L2 misses reduce by only 3 (2,032 → 2,029)

Why This Parameter Has This Effect:
  - Small working set (48KB) fits in all L2 configurations tested
  - L1D already handles 96.56% of accesses effectively
  - L2 sees only 28,564 requests (L1D misses)
  - Of those, >93% hit in L2 regardless of size
  - Remaining ~2,000 misses are compulsory (unavoidable)

Performance Saturation Point:
  - Saturates at 256kB (5.2× the working set)
  - No improvement beyond 256kB
  - Demonstrates law of diminishing returns in cache sizing
  - For this workload: 128kB provides 99.995% performance of 1MB

Cost-Performance Trade-off:
  - 128kB L2: Best cost, 99.995% performance
  - 256kB L2: Saturation point, 100% performance
  - 512kB L2: 2× cost of saturation, no gain
  - 1MB L2:   4× cost of saturation, no gain

Recommendation:
  - Use 256kB L2 for this workload class
  - For larger matrices (e.g., 256×256), test again
  - Always size cache based on working set analysis

General Principle Learned:
  "Size caches to the working set, not arbitrarily large"

  Cache Size = Working Set × Safety Margin
  Where Safety Margin ≈ 2-5× depending on:
    - Temporal locality variability
    - Sharing between threads
    - Context switch overhead
